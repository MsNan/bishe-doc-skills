# 毕业设计任务书

任务书是学院/指导教师下达的「要完成什么、做到什么程度、何时完成」，偏任务与验收；开题报告才是学生论证「为什么做、怎么做」。不要把开题报告整篇复制进任务书。学校还要求写开题报告时，请用 `thesis-proposal` 技能。

## 先问清楚再写
动笔前向用户确认（缺什么问什么，不要自己编）：
1. 学校任务书模板（Word/表格栏目、是否已经部分填写）
2. 课题名称、专业、指导教师是否已定题
3. 已有的开题材料或功能清单（没有就只根据用户口述列任务，不虚构模块）
4. 学校规定的进度节点（开题、中期检查、查重、答辩）和成果要求（论文字数、图纸、答辩 PPT 等）

只填模板里已有的栏目；学校没有的栏目不要添加。学生信息、学号、指导教师姓名等只使用用户提供的内容。

## 常见栏目（以学校表格为准）
1. **课题名称**：与开题报告、论文封面保持一致，不擅自改题。
2. **主要任务与设计内容**：用条目列出要完成的工作（文献调研、系统设计、编码实现、测试、撰写论文等），每条写清范围，避免空话（如只写「完成系统开发」）。
3. **技术指标与验收要求**：必须可检查。例如「支持管理员、教师、学生 3 种角色，权限不可互相越权」「列表支持按名称搜索与分页」「核心接口需有测试用例并实际执行」。不要写无法验收的「国内领先」「性能最优」。
4. **应完成的成果**：按学校要求列（可运行系统、论文、开题/中期材料、答辩 PPT、图纸或数据库说明等）。学校没要求的不要自行加项；有代码仓库时写「以用户提供的仓库/本地项目为准」，不要编造仓库地址。
5. **进度安排**：表格（阶段 | 时间 | 主要工作），与学校节点对齐，留出中期检查、查重和修改时间。后续中期材料请用 `midterm-check` 技能对照本表填写。
6. **主要参考资料**：只列出用户提供或建议检索的方向（知网关键词、官方文档名称）；不编造作者、年份、页码。格式见 `thesis-writing` 技能。

## 写法要点
- 任务条目与技术指标要能对应：写了「用户管理」，指标里就要有可验收的权限或功能描述。
- 指标宁可少而具体，不要堆砌用不到的技术名词。
- 若用户已有代码，先用 `code-to-thesis` 核对功能，再写进任务，避免任务书写了系统里没有的模块。
- 输出按用户模板栏目填写；没有模板时给一份可粘贴的 Markdown，提醒用户自行转入学校 Word 表格。

## 红线
- 不代写指导教师意见、签字、教研室/学院审批意见。
- 不编造课题编号、下达日期、学时、学院盖章内容。
- 任务书是学校正式文件，写完后提醒用户交给指导教师审核后再打印或提交。
- 遵守学校关于使用 AI 辅助写作的规定，提醒用户自己核对和改写。
