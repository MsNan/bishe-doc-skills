# 答辩准备

## PPT 提纲（一般 12–18 页，讲 8–10 分钟，以学院要求为准）
1. 封面（题目、姓名、学号、指导老师）
2. 选题背景与意义（1 页，一个真实痛点）
3. 研究内容 / 主要工作（1 页）
4. 技术选型与系统架构（1–2 页，放架构图）
5. 功能模块图（1 页）
6. 数据库设计（1 页，E-R 图，不要放整张表格）
7. 核心功能与实现（3–5 页，每页一个功能：截图 + 一句话 + 关键点）
8. 难点与解决（1–2 页，最能体现个人能力）
9. 系统测试（1 页，用例数、发现并修复的问题）
10. 总结与不足、展望（1 页）
11. 致谢

原则：一页一个观点，字少图多，字号不小于 18；截图来自真实系统。

## 讲稿
按页写口语化讲稿，标注每页用时，总时长控制在要求内。演示环节写**演示脚本**：先登录哪个账号 → 展示哪 3 个功能 → 准备好测试数据；提前录好演示视频以防现场环境出问题。

## 常见提问（帮用户准备基于其系统的真实回答，不要替用户编经历）
- 这个系统和现有的 xx 平台有什么区别？创新点在哪？
- 为什么选这个技术栈？前后端怎么通信、怎么做的登录鉴权？
- 数据库为什么这样设计？这两张表是什么关系？
- 密码怎么存的？怎么防止越权 / SQL 注入？
- 某个功能的实现流程（让你现场讲代码）
- 测试是怎么做的？发现过什么 bug？
- 系统有什么不足？如果继续做会怎么改？
- 哪些部分是自己写的、用了哪些开源组件或 AI 工具？——如实回答，符合学校规定。

## 模拟答辩
用户要求时，扮演答辩老师，基于论文和代码每次提一个问题，用户回答后点评（准确性、是否答到点上），最后汇总薄弱点。
