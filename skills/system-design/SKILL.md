# 系统设计

## 4.1 总体架构
- 一句话说清分层：如「前端 Vue3 + Element Plus，后端 Express/Spring Boot 提供 RESTful 接口，MySQL 存储」。
- 架构图（mermaid 草稿）：表现层 → 业务层 → 数据层，标出鉴权（JWT）位置。
- 前后端分离要说明跨域、鉴权、文件存储方式。

## 4.2 功能模块设计
功能结构图（树状）：系统 → 前台/后台 → 模块 → 功能点。与需求分析章节的功能点一一对应。

## 4.3 数据库设计
1. **概念设计**：E-R 图，实体用矩形、属性用椭圆、联系用菱形并标 1:1 / 1:N / M:N。实体太多时画总体 E-R + 局部属性图。
2. **逻辑设计**：E-R 转关系模式，如「用户(用户ID, 用户名, 密码, 角色ID)」，下划线标主键。M:N 联系要拆成中间表。
3. **物理设计（数据表）**：每张表一个三线表：

| 字段名 | 类型 | 长度 | 允许空 | 主键 | 说明 |
| --- | --- | --- | --- | --- | --- |
| id | int | 11 | 否 | 是 | 主键，自增 |

   - 表名「表 4-1 用户表（sys_user）」写在表**上方**；图名写在图**下方**。
   - 有建表 SQL 时直接从 SQL 生成，字段说明取 COMMENT；不要凭空增加系统里没有的字段。
   - 说明密码字段存哈希（bcrypt 等），不存明文。

## 4.4 接口设计
表格：接口名称 | 请求方式 | URL | 参数 | 返回 | 说明。统一返回格式写一次即可（如 `{ code, msg, data }`）。只列核心接口，完整清单放附录。

## 4.5 关键流程设计
登录鉴权、下单/审核等 2–3 个流程配时序图（mermaid sequenceDiagram 草稿），说明每一步谁调用谁、失败怎么处理。
